# 电话 ASR 多轮压力测试（2026-08-12）

## 测试规模

本轮由三组独立语料并行测试，内容互不复用：

- A：日常电话、否定纠正、打断、短口语，540 次推理。
- B：数字、日期、金额、IP/端口、英文专名、同音词、标点，540 次推理。
- C：长句、连续句、停顿、低声、噪声、首尾截断与右上下文，144 次推理。
- 主流程：两段现有真实电话录音各重复 5 次，再生成 12 个增益/噪声变体，共 22 次。

合计 1,246 次推理。三组模型测试均包含 X-ASR、SenseVoice、Paraformer，并至少重复三次。
全部语料和结果位于 `.nexus-test/asr-benchmark`，不进入 APK。

## 主要结果

| 测试组 | X-ASR CER | SenseVoice CER | Paraformer CER |
|---|---:|---:|---:|
| A 日常电话 | 2.38% | 2.91% | 3.44% |
| B 数字/专名声学 CER | 3.50% | 5.73% | 7.43% |
| C 长句与尾部上下文 | 0.53% | 0.53% | 1.06% |

所有三轮重复的归一化输出均 100% 一致。错误主要是确定性的模型、音频或切段错误，未发现
同一音频在相同模型上随机漏字。

## 首部、中部和尾部

- A 组刻意裁切开头后，X-ASR CER 从 1.33% 升到 5.96%；SenseVoice 从 1.99% 升到
  7.29%；Paraformer 从 2.65% 升到 6.62%。电话必须继续保留 pre-roll。
- B 组 X-ASR 声学错误率按区域为首部 1.71%、中部 3.20%、尾部 5.69%，说明问题并不只在
  首字，专名和数字场景中的句中、句尾仍会出错。
- C 组 X-ASR 补 1 秒静音右上下文时没有漏尾字；去掉右上下文后，6 个样本在三轮中稳定
  产生 18 次漏尾字，CER 从 0.53% 升到 2.11%。正常电话 endpoint 会继续接收约 1.2 秒
  静音，但异常取消、录音中断、提前 reset 和尾部丢帧仍需避免。
- 280 ms 句中停顿没有造成退化；超过当前 1.2 秒 endpoint 的停顿仍可能在电话中切成两句。

## 音量、噪声和短词

- A 组 22% 音量与 clean 的 CER 相同。
- 两段真实电话录音降低到 10% 音量后，X-ASR 输出仍与原录音完全一致。
- 20 dB SNR 基本稳定；10 dB 和 5 dB SNR 开始出现明显句中替换。
- “嗯”“喂”等极短口语在三个模型上都会稳定误识别，不能用长句 CER 代表短词能力。
- 低音量能被模型识别，不代表免提播放期间一定达到 barge-in 的声学触发门槛；两条判定链路
  必须分开评估。

## 数字、专名和标点

- X-ASR 数字语义准确率 100%，SenseVoice 95.56%，Paraformer 97.78%。
- 三个模型都倾向输出口语汉字数字，未转换成目标阿拉伯数字格式。严格业务 CER 34.87% 至
  38.94% 主要是格式差异，不能称为听写错误率；需要独立 ITN/格式化处理。
- 英文专名准确率：X-ASR 80.00%，SenseVoice 52.31%，Paraformer 41.54%。
- X-ASR 是唯一原生输出标点的候选，但 A 组标点完全匹配率仅 10%，B/C 平均标点准确率约
  48.68%/60.53%。SenseVoice 和 Paraformer 不输出标点。

## 结论

1. 当前仍保留 X-ASR：三组综合准确率、英文专名和标点均优于另外两种本地候选。
2. 继续保留电话 pre-roll 和 endpoint 后的静音右上下文，不能为了降低延迟提前丢弃首尾音频。
3. 下一项模型外改进应是独立中文 ITN/数字格式化与更可靠的标点恢复，而不是换回 Whisper。
4. 真实电话的剩余重点是实机 AEC 与 barge-in 触发率；合成语料不能证明低声在扬声器播放时
   一定触发，也不能量化真实回声抑制效果。
5. 批量测试期间 CPU 满载，子组 RTF 仅标记为 `latency under contention`，不用于延迟排名。
